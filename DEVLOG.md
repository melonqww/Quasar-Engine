# Публичный Devlog Quasar Engine

Короткие заметки о важных этапах и выводах проекта. Здесь остаётся общий ход развития; подробные технические записи, проверки и рабочие задачи ведутся отдельно.

## 2026-09-30 — Начали визуальную основу редактора

По запросу автора перенесли компоновку выбранного концепта в работающий интерфейс: нейтральные серые панели с янтарным акцентом, рабочие вкладки, компактные действия, отдельную вкладку сцены, вертикальную панель инструментов и Console. Общая тема используется в Stage 0 и document mode. Basic/Advanced пока меняет только видимость технических подробностей; Code, Advisor и неподключённые Play-контролы показаны отключёнными.

В document mode 3D-камера теперь выводит сцену в отдельную texture, размер которой следует площади viewport и DPI; UI рисует отдельная оконная камера. Существующие сценовые команды, импорт и MCP используют прежнюю общую сессию. Сборка, workspace-тесты и Clippy прошли; оба режима запущены и осмотрены на снимках. Доступ Computer Use к окну не был разрешён, поэтому клики/drag через ОС остаются для ручной приёмки.

## 2026-09-29 — Начали библиотеку ассетов

В постоянном document mode появилась вкладка Assets: каталог читает sidecar metadata со стабильным AssetId, показывает поиск и статусы, а локальный импорт копирует поддерживаемые GLB, PNG/JPEG и WAV внутрь проекта. Добавлены базовые проверки содержимого и staging-публикация исходника вместе с metadata. Это первый срез этапа 3: реимпорт, URL-загрузка, привязка к сцене и MCP-инструменты пока не входят. Сборка workspace проверена; ручной импорт через окно ещё нужно принять.

## 2026-09-30 — Подключили модели, повторный импорт и MCP для ассетов

К объектам можно привязать GLB по стабильному AssetId; команда проходит через общую сессию и поддерживает Undo/Redo. Editor и Player отображают назначенную модель из project asset root. Импорт, reimport и direct URL download выполняются фоновыми jobs со статусом, байтовым прогрессом и отменой; невалидный reimport не публикует staged-файл поверх предыдущего. Добавлены MCP tools для списка ассетов, импорта, reimport, статуса/отмены jobs и назначения модели.

URL-функция принимает прямые HTTP(S) ссылки без редиректов, ограничена 90 секундами и 512 MiB, проверяет адреса и использует установленный `curl.exe`/`curl`. Проверка 3.7 прошла 69 workspace-тестов, Clippy с `-D warnings`, rustfmt и `git diff --check`. Подтверждены локальный import/reimport, сохранение last-good при ошибке, malformed input, cancellation, библиотека, model reference, Player preview, Undo/Redo и Save/reopen через MCP; Editor/Player также сняты на временном проекте с загруженной GLB-моделью. Открыты только live click/drop-проверка UI и отдельный MCP-процесс против открытой Editor-сессии: окно не было доступно через Computer Use, а внешний loopback-клиент сбрасывал соединение. Успешное скачивание с публичного URL отдельно не проверялось.

## 2026-10-01 — Проверили MCP с отдельным процессом

Отдельный MCP-клиент подключился к работающему Editor и прошёл импорт GLB, обновление каталога, назначение модели, Undo/Redo и Save. В процессе исправили нестабильный опрос заданий на Windows. Повторно прошли 73 workspace-теста и проверки Clippy/форматирования. Проверки клика/перетаскивания в окне и успешной загрузки с публичного URL пока не завершены.

## 2026-09-28 — Подключили первое редактирование документа

В режиме открытия `ProjectDocument` появился отдельный редакторский экран: дерево объектов, выбор, создание и удаление, инспектор имени и локального transform, инструменты Move/Rotate/Scale, Undo/Redo и сохранение. Сцена отображает авторские объекты временными кубами; полноценный viewport, picking и контентные компоненты ещё впереди.

Редактор и MCP теперь используют одну `EditorDocumentSession`. MCP умеет проверить команду без изменения документа, применить её с `expected_revision`, отменить/повторить действие и сохранить проект. `cargo test --workspace` и сборочные проверки проходят, включая проверки preview, stale revision, группировки и отмены transform-жеста, Undo/Redo и повторного открытия сохранённого документа. Ручная проверка самого окна остаётся следующей.

## 2026-09-29 — Проверили запись сцены через MCP

Подняли Editor document mode на временной копии Stage 1 fixture и подключили отдельный stdio MCP-клиент к живой сессии. Все 8 tools обнаружены. Через MCP проверили preview без мутации, конфликт устаревшей revision, create/rename/transform/reparent, удаление родителя вместе с ребёнком, Undo/Redo, Save, отказ некорректной ссылки на родителя и отсутствие частичного изменения. После закрытия Editor новый процесс повторно открыл сохранённый проект; через MCP подтвердились transform и parent-child связь.

Editor открыл окно, отрисовал дерево, inspector, viewport и placeholder-геометрию. Ввод через UI-кнопки и drag-жесты отдельно вручную не нажимали; этот пункт остаётся для ручной приёмки.

## 2026-09-28 — Заложили общий слой редактирования сцены

Editor document mode теперь держит постоянный `ProjectDocument` в общей сессии с revision, dirty state и атомарным save. Добавили команды создания и удаления поддерева, переименования, transform и reparent; неверная команда не публикуется в сессии. Undo/Redo хранит ограниченную историю по сценам, а изменения transform во время одного жеста собираются в одну запись. UI-панели и MCP пока не вызывают write-команды; следующим будет подключение дерева, inspector и viewport.

## 2026-09-27 — Подключили SceneDocument к Player и MCP

Player теперь может открыть постоянный `ProjectDocument` отдельно от Stage 0 snapshot и показать активную сцену с иерархией и локальными transforms. Добавили локальный stdio MCP-адаптер: он подключается к проекту, уже загруженному в Editor, и пока умеет только читать состояние проекта и сцены. Сквозная проверка на одном документе подтвердила одинаковые ID и состав сцены. Рендер-компоненты, ассеты и запись через MCP остаются следующими этапами.

## 2026-09-27 — Закрыли этап 0

После автоматических и ручных проверок приняли базовую связку Editor, runtime и Player, включая пробу анимационных вкладок и сохранения проекта. Этап 0 закрыт. Тестовый RobotExpressive не подходит как постоянная модель, поэтому оставляем его только в fixture; новую модель выберем позднее при работе с ассетами. Следующий шаг — определить постоянный формат SceneDocument и путь его чтения независимым Player.

## 2026-09-27 — Заложили постоянный формат проекта

Начали этап 1 с требований и модели данных: проект теперь описывается отдельными `ProjectDocument` и `SceneDocument` со стабильными UUID, ID активной сцены, иерархией, локальными transforms и versioned component envelopes. Добавили проверку документа и атомарное сохранение одного JSON project bundle. Player и MCP пока не подключены к новому формату; это следующие пункты этапа.

## 2026-09-26 — Подключили анимационный runtime к Editor и Player

Добавили общую для Editor и Player пробу воспроизведения: ключи движения двери и событие звука, импортированные клипы персонажа, вкладки Scene Timeline и Clip Preview, сохранение и повторное открытие snapshot. Технический smoke-запуск подтвердил, что клипы и событие воспроизводятся. Теперь предстоит проверить ручное редактирование, сохранение и переход проекта в отдельный Player; удобство вкладок и внешний вид персонажа ещё оцениваются.

## 2026-09-25 — Проверили основу Stage 0

На целевой машине проверили раннюю связку редактора и отдельного Player: тестовая сцена отображается, базовое управление и столкновение со стеной работают, дверь взаимодействует со звуком. Это подтвердило пригодность прототипа для следующих технических экспериментов, но пока не делает его полноценным редактором и не фиксирует окончательный выбор архитектуры.

## 2026-09-25 — Подготовили основу для эксперимента с анимацией

Добавили в снимок проекта описание ключевой анимации, звукового события и ссылки на импортированные клипы. Это подготовка данных для следующего эксперимента: само воспроизведение анимаций и удобство работы с ними ещё предстоит проверить.

## 2026-09-24 — Выбрали визуальную отправную точку

Согласовали предварительное направление интерфейса редактора: компактная компоновка с рабочими вкладками и уровнями Basic и Advanced. Это изменяемый прототип для будущей реализации, а не готовый интерфейс.
